# Migration Guide: bevy\_archie 0.4.x → 0.5.x (Bevy 0.20)

`bevy_archie` `0.5.x` is a crate-level minor release. It stays on **Bevy 0.20** — no Bevy
migration is required — and adds a new persistence backend, a virtual-keyboard correctness fix,
and an examples refresh.

> **Status:** Bevy 0.20.x. `bevy_archie` `0.5.x` is the new main line on Bevy 0.20. The previous
> `0.4.x` line continues to receive maintenance patches on the
> [`bevy-0.19`](https://github.com/greysquirr3l/bevy-archie/tree/bevy-0.19) branch's successor
> while `main` carries 0.5.x.
>
> **MSRV note:** unchanged at **Rust 1.97.1**.

For the Bevy 0.19 → 0.20 upgrade itself, see the
[official Bevy migration guide](https://bevy.org/learn/migration-guides/0-19-to-0-20/) and this
repo's [Bevy 0.19 → 0.20 notes](BEVY_0.19_TO_0.20_MIGRATION.md).

## Controller config persistence → Bevy `SettingsPlugin`

`ControllerConfig` is now a Bevy **`SettingsGroup`**, so persistence goes through Bevy's
`SettingsPlugin` instead of the crate's hand-rolled JSON file handling. The settings are
written as TOML at `{preferences_dir}/{app_id}/settings.toml`, with crash-resistant atomic
writes and a browser local-storage fallback on web.

The old JSON helpers are deprecated and will be removed in `0.6.0`:

| Deprecated                                | Replacement                                 |
| ----------------------------------------- | ------------------------------------------- |
| `ControllerConfig::load_or_default()`     | Loaded automatically by `SettingsPlugin`    |
| `ControllerConfig::load_from_file(p)`     | Loaded automatically by `SettingsPlugin`    |
| `ControllerConfig::save_default()`        | `SaveSettingsDeferred` / `SaveSettingsSync` |
| `ControllerConfig::save_to_file(p)`       | `SaveSettingsDeferred` / `SaveSettingsSync` |
| `ControllerConfig::default_config_path()` | Owned by `SettingsPlugin` (see the app id)  |

**Before**

```rust
use bevy::prelude::*;
use bevy_archie::prelude::*;

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .add_plugins(ControllerPlugin::default())
        .add_systems(Startup, load_config)
        .run();
}

fn load_config(mut config: ResMut<ControllerConfig>) {
    *config = ControllerConfig::load_or_default();
}
```

**After**

```rust
use bevy::prelude::*;
use bevy::settings::{SaveSettingsDeferred, SaveSettingsSync, SettingsPlugin};
use bevy_archie::prelude::*;
use std::time::Duration;

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .add_plugins(ControllerPlugin::default())
        // Loads `ControllerConfig` from disk and applies it over the defaults.
        .add_plugins(SettingsPlugin::new("com.example.mygame"))
        .add_systems(Update, save_config_on_change)
        .add_systems(Last, save_on_exit)
        .run();
}

/// Debounced save — the write is scheduled shortly after the last change.
fn save_config_on_change(config: Res<ControllerConfig>, mut commands: Commands) {
    if config.is_changed() && !config.is_added() {
        commands.queue(SaveSettingsDeferred(Duration::from_millis(250)));
    }
}

/// Immediate save on shutdown, so nothing is lost when the window is closed.
fn save_on_exit(mut commands: Commands) {
    commands.queue(SaveSettingsSync::IfChanged);
}
```

`ControllerPlugin::with_settings(app_id)` is a shorthand that adds the `SettingsPlugin` for you:

```rust
App::new()
    .add_plugins(DefaultPlugins)
    .add_plugins(ControllerPlugin::with_settings("com.example.mygame"))
    .run();
```

To combine it with the other plugin options, use the builder method:

```rust
ControllerPlugin::with_icon_path("icons/controller").with_settings_app_name("com.example.mygame")
```

Notes:

- `ControllerConfig::current_layout` is runtime state, not a user preference, so it is
  excluded from the persisted file (`#[reflect(ignore)]`). `forced_layout` *is* persisted.
- The JSON file written by the old helpers is **not** migrated automatically. Read it once with
  `serde_json` and copy the values into `ControllerConfig` if you need to carry settings over.
- `dirs` is still used by the deprecated helpers; it is removed together with them in `0.6.0`.
- The `bevy_settings` Bevy feature is now a **hard** dependency of the crate. If you disable
  Bevy's default features, add `bevy_settings` to your own feature list.

## Virtual keyboard: the cursor is now a grapheme index

`VirtualKeyboard::cursor` was a **byte offset** into `VirtualKeyboard::buffer`. It is now a
**grapheme-cluster index**, and `VirtualKeyboard::max_length` is counted in grapheme clusters
to match Bevy's `EditableText::max_characters`.

This fixes a crash. The old byte-indexed buffer inserted at `self.cursor` while advancing the
cursor by one character, so typing a multi-byte character (an accented letter, an emoji) and
then another character tripped `String`'s char-boundary assertion:

```text
buffer after é: "é" cursor=1
panicked: assertion failed: self.is_char_boundary(idx)
```

Backspace also deleted a single *byte* rather than a whole character.

**If you read or write `cursor` directly**, you need to change your code. The most common
pattern — reading the cursor to slice the buffer — becomes:

```rust
// before: byte offset
let byte_offset = keyboard.cursor;
let rest = &keyboard.buffer[byte_offset..];

// after: grapheme index — use the grapheme API
use unicode_segmentation::UnicodeSegmentation;
let rest: String = keyboard.buffer.graphemes(true).skip(keyboard.cursor).collect();
```

If you only ever use the provided methods (`add_char`, `backspace`, `cursor_left`,
`cursor_right`, `clear`), nothing changes.

The `unicode-segmentation` crate is a new direct dependency. If your own code needs to work
with the buffer, add it to your `Cargo.toml` as well.

## Examples now use Bevy's `bsn!` scene notation

The examples were converted from `commands.spawn((...))` bundles to
`commands.spawn_scene(bsn! { ... })`. This is an **examples-only** change — no library API was
affected — but it does mean the example source no longer matches what you may have copied from
`0.4.x`.

The observable result is identical: the same components, with the same values, on the same
entities. If you want to follow along, the equivalent of the old form is:

```rust
// before (0.4.x)
commands.spawn((
    Text::new("Hello"),
    TextFont { font: FontSource::sans_serif(), font_size: FontSize::Px(18.0), ..default() },
));

// after (0.5.x)
commands.spawn_scene(bsn! {
    Text("Hello")
    TextFont {
        font: FontSourceTemplate::Generic(GenericFontFamily::SansSerif),
        font_size: FontSize::Px(18.0),
    }
});
```

Two library types gained a `Default` impl so that they can be used as scene components
(`bsn!` components must be `Clone + Default`):

- `ButtonIcon::default()` is `FaceDown`
- `GameAction::default()` is `Confirm`

## Notes for downstream consumers

- **The library compiles unchanged for most consumers.** Existing code keeps working; the
  deprecated JSON helpers still function and now emit deprecation warnings.
- **No new feature flags were added or removed.** Existing `icons`, `virtual_keyboard`,
  `remapping`, `motion-backends`, and `dualsense` features continue to work identically.
- **`bevy_settings` is now a required Bevy feature** for this crate.
- **MSRV unchanged at Rust 1.97.1.**
